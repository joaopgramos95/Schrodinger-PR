Project Workflow: Formalizing the Cubic-NLS Phase-Retrieval Theorem in Lean
==========================================================================

Purpose
-------

This file is an execution-ready recipe for formalizing ONE central theorem —
the phase-retrieval theorem for the 1D cubic NLS — in Lean 4 / Mathlib.

It is the project-specific descendant of BlackBox_Workflow.txt (also in this
folder). The generic 5-step idea is unchanged:

1. read the paper;                    <- ALREADY DONE (see paper_blueprint.tex)
2. make a Blueprint;                  <- ALREADY DONE (paper_blueprint.tex)
3. split the Lean project into files; <- ALREADY DONE (appendix of the blueprint)
4. produce a first scaffold;          <- you start here
5. replace axioms by real proofs.     <- the bulk of the work

Because Steps 1-3 are already done for this project, DO NOT re-read the paper
from scratch or invent a new blueprint. Use the artifacts provided.

What is different from BlackBox_Workflow.txt (READ THIS):
- The blueprint already exists as a compiled, dependency-annotated LaTeX file
  paper_blueprint.tex (144 numbered results, full \uses graph). Use it as THE
  map. Do not produce a new Blueprint.md unless you are only re-serializing
  paper_blueprint.tex into Markdown.
- The Lean statement to verify already exists in showcase.lean and has been
  checked to correspond to the paper's mathematics (see TEX_MATHLIB_AUDIT.md).
- The Mathlib version, the foundational entry points, the file split, the one
  missing foundational leaf, and the risk map are all known and recorded below.

The target (do not drift from this)
------------------------------------

The final Lean theorem is `phase_retrieval_interval` in showcase.lean
(Corollary "Equality on any time interval"), of which `phase_retrieval_cubic_NLS`
(Theorem 1.1) is a proved special case. In the blueprint these are
\cref{cor:interval-version} and \cref{thm:main} in the chapter
\chapter{Completion of the phase-retrieval proof}.

GOAL: showcase.lean compiles with NO `sorry`, and `#print axioms
CubicNLS.phase_retrieval_interval` reports only Lean's standard axioms
(propext, Classical.choice, Quot.sound) — i.e. no project axioms and no sorryAx.

Rules on showcase.lean:
- The STATEMENTS `phase_retrieval_interval`, `phase_retrieval_cubic_NLS`, and the
  structure `GlobalSolution` in showcase.lean are the statements of record. Do NOT
  change them. You may only replace the `sorry` by a real proof.
- The definitions inside showcase.lean (the space L2, the propagator `freeProp`,
  the class `GlobalSolution`, the modulus/pairing conventions) are canonical. The
  project in Lean_Code must reuse them or define them so that they are definitionally
  the same, so that the final proof plugs into showcase.lean unchanged. The cleanest
  route: factor these canonical definitions into an early Lean_Code file and have
  showcase.lean import it, OR develop Lean_Code and, in the very last step, fill the
  `sorry` in showcase.lean with `exact CubicNLSPhaseRetrieval.phase_retrieval_interval ...`.
  Whichever route, the statement text of showcase.lean must be byte-for-byte unchanged.

Do NOT start by trying to prove the final theorem. First build the project bottom-up.

BEFORE writing any definition or proof, `#check` every foundational entry point the
project relies on, to confirm the exact names at this revision. These are CONFIRMED to
exist at commit 81a5d25, but their spellings must be verified in your environment:

    MeasureTheory.Lp.fourierTransformₗᵢ          -- L² Fourier transform as ≃ₗᵢ[ℂ]
    MeasureTheory.Lp.norm_fourier_eq             -- ‖𝓕 f‖ = ‖f‖
    MeasureTheory.Lp.inner_fourier_eq            -- ⟪𝓕 f, 𝓕 g⟫ = ⟪f, g⟫
    MeasureTheory.Lp.fourier_toTemperedDistribution_eq
    TemperedDistribution.MemSobolev              -- fractional Sobolev predicate on 𝓢'
    TemperedDistribution.MemSobolev.lineDerivOp  -- p = 2 only
    TemperedDistribution.MemSobolev.laplacian    -- p = 2 only
    TemperedDistribution.besselPotential

NAMING NUANCE (important): the p=2 Fourier characterization is NOT named
`memSobolev_two_iff_fourier` (that string appears only in a Mathlib docstring). The real
lemmas are `TemperedDistribution.memSobolev_iff_exists_smulLeftCLM_fourier` and
`TemperedDistribution.memSobolev_besselPotential_iff`. `#check` these and alias the one
you use.

Also confirm the presence of the other foundational leaves (all verified present):
Gaussian/oscillatory Fourier integral (Analysis/SpecialFunctions/Gaussian/FourierTransform),
maximum modulus (Analysis/Complex/AbsMax, PhragmenLindelof), du Bois-Reymond
(Analysis/Distribution/AEEqOfIntegralContDiff), FTC / 1D absolute continuity
(MeasureTheory/Integral/IntervalIntegral/{Basic,FundThmCalculus,AbsolutelyContinuousFun}),
Banach–Alaoglu / weak-dual, convolution/Young, simple-function/Schwartz density in L^p.

THE ONE MISSING FOUNDATIONAL LEAF: Mathlib's Gronwall.lean has only the constant-coefficient
derivative form. The variable-coefficient INTEGRAL Grönwall inequality is NOT in Mathlib. It
is stated in the blueprint as \cref{lem:integral-gronwall} and must be proved from the FTC.
It is off the main path (only \cref{cor:linear-common-potential} uses it), so it can be done
last or skipped if that corollary is out of scope.

Step 4. First scaffold: real definitions, narrow named axioms for lemmas
------------------------------------------------------------------------

Turn each numbered blueprint result into a Lean declaration. Definitions become REAL Lean
definitions wherever feasible; lemmas/props/theorems may TEMPORARILY be narrow named axioms
whose statement is the faithful Lean translation of the blueprint statement. One axiom per
blueprint result — never bundle unrelated facts.

Build order for the scaffold: ScalarMixedNorms, then FourierSobolev, then the rest per Step 3.

THE FIRST REAL DESIGN TASK is FourierSobolev (Module 1). Mathlib's TemperedDistribution.MemSobolev
is a PREDICATE, not a bundled Hilbert space. You must design the H^s interface before scaffolding
downstream: decide whether to build a bundled H^{1/2} Hilbert space (via ⟨ξ⟩^s \hat f ∈ L², as in
\cref{def:Hs-space}) or to work through MemSobolev; then fix H^{-1/2} and the COMPLEX-BILINEAR
H^{-1/2}–H^{1/2} pairing (\cref{def:Hs-neg-pairing}, the extension of ∫ T φ — NOT the sesquilinear
inner product); then H^s_loc (\cref{def:Hs-loc}). Every later module consumes this interface, so
choose it carefully. The proof that the Gagliardo seminorm equals the Fourier norm is supplied by
\cref{thm:fourier-gagliardo}.

Rules:
- definitions real whenever possible;
- theorem/lemma statements may temporarily be `axiom`s with precise statements;
- each axiom narrow and named after its blueprint \label (e.g. `axiom thm_hom_strichartz : ...`);
- never a giant catch-all axiom; NEVER an axiom that restates a central step under a vague name
  (no `axiom strichartz`, `axiom carleman`, `axiom halfspace_uc` as opaque black boxes — these
  are the mathematical content and must become theorems);
- run Lean after each file or small group of files.
